    Playwright Ecosystem Update Report

    Date: January 1, 2026 Scope: December 2025 (Last Month) & Late November 2025

    The Playwright ecosystem has seen significant activity in the last month, headlined by the v1.57 release and the rapid iteration of the new Playwright MCP (Model Context Protocol) Server for AI integration.

    ---

    1. Core Framework Updates (v1.57.0)

    *Released late November 2025; currently the stable version for Dec/Jan.*

    #### 🚀 New Feature: "Speedboard" in HTML Reporter
    • Impact: Major (Productivity)
    • Summary: A new "Speedboard" tab has been added to the standard HTML reporter. It visualizes test execution times, sorting them by slowness to help teams instantly identify performance bottlenecks in their test suite.
    • Action Item: Run npx playwright show-report after your next test run and check the Speedboard tab to identify your top 5 slowest tests for optimization.


    #### ⚠️ Breaking Change: Switch to "Chrome for Testing"
    • Impact: Critical / Breaking
    • Summary: Playwright has switched its default browser binary from standard Chromium to Chrome for Testing. This ensures the browser environment matches the stable Chrome release more closely, reducing "works on my machine" issues.
    • *Note:* Linux Arm64 machines will continue to use Chromium.
    • Action Item: If you pin browser versions in Docker or CI, ensure you are using the official Playwright v1.57+ Docker images which handle this switch automatically. Watch for subtle rendering differences if your app relies on non-standard Chromium behaviors.


    #### 🛠 API Update: Smarter Web Server Waiting
    • Impact: Minor (Quality of Life)
    • Summary: The webServer config now supports a wait property that accepts a Regular Expression. Playwright will wait for the server's stdout to match this regex before starting tests, replacing fragile fixed timeouts.
    • Action Item: Update your playwright.config.ts:
        webServer: {
      command: 'npm run start',
      wait: { stdout: /Listening on port \d+/ }, // new regex support
    }


    #### 🌐 Service Worker Enhancements
    • Impact: Major (For PWA testing)
    • Summary: Network requests initiated by Service Workers are now fully captured and can be routed/mocked via context.route(). Console logs from Service Workers are also now emitted via the worker.on('console') event.


    ---

    2. AI & Ecosystem Updates (December 2025)



    #### 🤖 Playwright MCP Server (v1.0.7 - v1.0.12)
    • Date: December 2025
    • Impact: Major (AI Integration)
    • Summary: Microsoft released multiple updates to the Playwright Model Context Protocol (MCP) Server. This tool allows AI coding agents (like GitHub Copilot or other LLMs) to directly launch, control, and inspect Playwright browsers to "see" and test applications autonomously.
    • Key Updates:
    • Auto-Install: The server now automatically detects and installs missing browsers (v1.0.12).
    • Console Output: Improved real-time logging for AI agents to debug failures (v1.0.9).
    • Security: Removed shell execution capabilities for safer browser installation (v1.0.12).


    #### 🧩 VS Code Extension Updates
    • Date: Late Nov / Dec 2025
    • Impact: Minor
    • Summary: The official extension received performance optimizations, specifically scanning only necessary files when running tests to improve startup speed in large monorepos.


    ---

    3. Deprecations & Removals

    • Manifest V2 Support Dropped: As of v1.57, Playwright no longer supports Chromium extensions using Manifest V2, aligning with the broader Chrome ecosystem deprecation.
    • Action Item: If you test browser extensions, ensure your test fixtures are updated to Manifest V3.
    • page.accessibility Removed: This API, deprecated 3 years ago, has been fully removed. Teams should use the axe-core integration for accessibility testing.


    Summary of Action Items for QA Engineers

    1. Upgrade to v1.57: npm install -D @playwright/test@latest to get the new Speedboard and Chrome for Testing binaries. 2. Check CI Pipelines: Verify that the switch to "Chrome for Testing" hasn't introduced visual regression in your screenshots. 3. Optimize Slow Tests: Use the new Speedboard to cut down total CI time by fixing the slowest 10% of your tests. 4. Explore MCP: If your team uses AI coding assistants, investigate setting up the Playwright MCP server to allow the AI to write and verify its own tests.

    Selenium Java Ecosystem Report: January 1, 2026



    Executive Summary: The most significant development is the release of Selenium 4.39.0 on December 6, 2025. This update brings substantial improvements to Selenium Grid's performance by replacing Guava caches with Caffeine, expands BiDi (Bidirectional) functionality, and continues the effort to improve Java type safety with JSpecify annotations. Browser driver updates include support for Chrome 143 and continued stability with GeckoDriver 0.36.0.

    ---

    1. Major Release: Selenium 4.39.0

    • Date: December 6, 2025
    • Source: SeleniumHQ GitHub Releases / Maven Central
    • Impact: Major
    • Summary:
    • Grid Performance: A significant architectural change in Selenium Grid involves migrating internal caching from Guava's CacheBuilder to Caffeine. This is expected to improve performance and concurrency handling for Grid nodes.
    • BiDi Emulation: The Java bindings have added new support for the BiDi (Bidirectional) emulation module, allowing for more advanced device and network emulation capabilities directly through the WebDriver BiDi protocol.
    • Shadow DOM: Enhancements to Shadow DOM element normalization, improving stability when interacting with deeply nested shadow roots.
    • Cookie Handling: Added support for SameSite=default cookie attribute values, aligning with modern browser security standards.
    • Action Items:
    • Update selenium-java dependencies to 4.39.0 in Maven/Gradle.
    • If maintaining a custom Selenium Grid infrastructure, monitor node memory usage after upgrade due to the caching library switch.
    • Test Shadow DOM locators in your suite to ensure the "normalization" changes haven't altered behavior for your specific app structure.


    2. Browser Driver Updates

    • Date: Late December 2025
    • Source: Chrome for Developers / Mozilla
    • Impact: Major
    • Summary:
    • ChromeDriver 143: Released to support Chrome 143 (Stable Dec 2025). This version supports new Chrome features including CSS anchored fallback container queries and the Web Smart Card API.
    • GeckoDriver 0.36.0: Remains the current stable driver for Firefox. It continues to support the latest Firefox releases (v146.x) with stability fixes for the Marionette protocol.
    • Action Items:
    • Ensure your CI/CD pipelines are using ChromeDriver 143 if your test browsers have auto-updated to Chrome 143.
    • Selenium Manager (included in Selenium 4.x) handles this automatically, but manual grid setups require binary updates.


    3. Java Binding Enhancements (JSpecify)

    • Date: December 2025 (Ongoing)
    • Source: Selenium GitHub Changelog
    • Impact: Minor (Maintenance)
    • Summary:
    • The Selenium team is actively adding JSpecify annotations (e.g., @Nullable) across the Java codebase. This improves null-safety analysis for developers using modern IDEs (IntelliJ, Eclipse) and static analysis tools.
    • Action Items:
    • No code changes required, but you may notice improved IDE warnings regarding potential NullPointerException risks in your test code when interacting with WebDriver APIs.


    4. Security & Deprecations

    • Date: December 2025
    • Source: Official Selenium Blog / GitHub
    • Impact: Minor
    • Summary:
    • Deprecation Cleanup: Continued removal of deprecated classes (e.g., legacy LocationContext, WebStorage interfaces in favor of BiDi/CDP equivalents) is happening.
    • Telemetry Note: Selenium Manager has identified anomalies with users locked on older Chrome versions (v127), prompting a reminder to ensure test environments are not artificially pinned to vulnerable browser versions.
    • Action Items:
    • Review build logs for deprecation warnings.
    • Ensure your local and CI environments are not pinning Chrome to versions older than v140 to avoid security risks and compatibility issues with Selenium 4.39.0.
